# Customer Discovery for Product Teams — Sample Lenny Podcast Transcript Fixture

**NOTE: This is a clearly labeled sample fixture for demo/RAG testing.**

Lenny Rachitsky: Priya, how should PMs run customer discovery without building the wrong thing faster?

Priya Nair: Start with problems, not solutions. The goal of discovery is to reduce uncertainty about whether a problem is urgent, frequent, and valuable enough to solve. I use a simple filter: if users aren't already hacking together a workaround, the problem might not be painful enough.

Lenny: How many interviews are enough?

Priya: For a new problem space, fifteen to twenty interviews across segments. Stop when you hear repeating patterns — same words, same workarounds, same objections. If interview seven contradicts interview six, keep going.

Lenny: Common discovery mistakes?

Priya: Leading questions, demoing too early, and only talking to friendly users. Also, conflating feature requests with underlying jobs. When someone asks for an export button, ask what decision they're trying to make with the exported data.

Lenny: How does discovery connect to growth?

Priya: Discovery informs which loops are worth building. If users don't perceive value within the first session, no amount of referral mechanics will save you. Discovery validates the reward in your activation loop before you scale acquisition.

Lenny: Templates or frameworks?

Priya: I like opportunity solution trees — outcome at the top, opportunities from research, solutions as hypotheses. Pair every solution with a measurable assumption you can test in a week, not a quarter.

Lenny: Advice for founders?

Priya: Write down what would falsify your belief. If you can't name evidence that would change your mind, you're not doing discovery — you're doing confirmation.
